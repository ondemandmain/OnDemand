# Contributing to On-Demand

Thanks for your interest! Contributions help this project improve and grow.

Getting started

1. Fork the repository and create a feature branch: `feature/short-description`.
2. Keep changes focused and one concern per pull request.
3. Write tests for any non-trivial logic (order simulation, portfolio math).

Branch & PR workflow

- Base branch: `main`.
- Create feature branches from `main` and open a PR against `main`.
- Use a descriptive PR title and include a short summary of changes.
- Link related issues (e.g., `Fixes #12`).

Code style

- Keep code readable and idiomatic for the component's language.
- Use sensible commit messages (imperative mood, short summary).

Review checklist (for PR authors)

- Tests added or existing tests updated.
- Documentation updated where behavior changed (README or `md/`).
- No sensitive keys or secrets in commits.

Communication

- Open issues for bugs or feature requests before large changes.
- Ask for help via Issues or Discussions if unsure about design direction.

Thanks — we appreciate clear, considerate contributions!
